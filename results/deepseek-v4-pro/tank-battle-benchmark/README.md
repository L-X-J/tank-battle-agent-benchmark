# STEEL FRONT — 钢铁前线

原创像素风坦克对战游戏（经典坦克大战核心玩法的原创实现）。保护你的基地，消灭每关 20 辆敌方坦克，一路打穿 35 个关卡。

- 全部图形由 Canvas 程序绘制（无任何外部图片/字体/音频文件）
- 全部音效由 Web Audio API 程序合成
- 零第三方依赖、零构建步骤、完全离线运行
- 游戏规则与渲染分离：核心逻辑可直接在 Node.js 中做确定性测试

## 技术栈

| 项目 | 实现 |
| --- | --- |
| 页面 | HTML5 + CSS3 |
| 逻辑 | 原生 JavaScript（ES2022 Modules），无框架 |
| 渲染 | Canvas 2D，逻辑尺寸 512×416（战场 416×416 + 信息栏 96） |
| 音频 | Web Audio API（程序合成） |
| 服务器 | Node.js 内置 `node:http`（`server.mjs`） |
| 测试 | Node.js 内置 `node:test` |
| 构建 | 无（不需要编译/打包） |

## 启动与测试

**必须先进入项目目录**（npm 会向上查找最近的 package.json，在其他目录运行会报 `Missing script`）：

```bash
# 在本项目目录（包含 package.json 的目录）下执行：
npm start     # 启动本地服务器 → http://localhost:8080
npm test      # 运行全部自动化测试（61 个用例）
```

> 项目根目录额外附带一个零依赖的 `./npm` 兼容脚本（`./npm start` / `./npm test`），
> 作为没有 npm CLI 的环境下的备用方案；有 npm 的环境直接使用标准命令即可，
> 两者行为一致。`package.json` 为完全标准的 npm 包。

## 打包与部署

本游戏是纯前端项目，部署到网站**不需要 Node 服务器、不需要构建/编译**，只要静态托管。

```bash
# 在本项目目录下执行：
npm run build    # 生成 dist/ 部署目录（27 个文件）
```

`dist/` 只包含运行必需的资源：

```text
dist/
├─ index.html
├─ styles.css
└─ src/**            # 全部 ES 模块
```

- 把 `dist/` 目录内的内容整体上传到任意静态托管即可：Nginx、Apache、GitHub Pages、Netlify、Vercel、Cloudflare Pages、对象存储（OSS/COS/S3 静态网站）等
- 所有引用路径均为相对路径，因此**既能在根路径部署，也能部署在子路径**（例如 `https://example.com/game/`）
- 游戏完全离线运行、零第三方依赖、无网络请求，托管在任何 HTTPS 或 HTTP 域名下均可直接游玩
- 本地预览用 `npm start`（http://localhost:8080），线上用静态托管；两者行为一致

> 已实测：`dist/` 通过纯静态服务器（python3 http.server）加载，浏览器进入主菜单 → 单人模式 `PLAYING`，控制台 **0 错误**。

## 游戏规则

- **目标**：保护基地，消灭每关全部 20 辆敌方坦克；完成第 35 关获得胜利
- **失败**：基地被任意阵营子弹击中（包括玩家误射），或所有玩家生命耗尽
- **生命**：每名玩家 3 条；死亡后在出生点重生（出生/重生均带短暂保护罩）
- **火力等级**（每名玩家独立，当前生命内持续）：
  - Level 0：普通子弹，同时最多 1 发
  - Level 1：高速弹
  - Level 2：双发（同时最多 2 发）+ 射击频率提升
  - Level 3：穿甲弹（可摧毁钢墙），保留前两级能力
- **死亡降级规则（固定）**：玩家死亡后火力等级降低 1 级（3→2→1→0），最低为 0
- **额外生命分数阈值**：不设阈值（规则固定；额外生命仅由道具提供）
- **友军误击**：玩家子弹击中另一名玩家不扣生命，但造成约 0.5 秒停顿
- **暂停**：暂停期间所有逻辑、计时、动画、道具倒计时、敌人与子弹全部停止

### 4 种敌方坦克

| 类型 | 特点 | 分数 |
| --- | --- | --- |
| 侦察兵 SCOUT | 普通速度、普通射速，1 点生命 | 100 |
| 突击兵 STRIKER | 移动速度明显更快，1 点生命 | 200 |
| 火力手 GUNNER | 射击频率更高、子弹更快，具备 BFS 路径搜索，1 点生命 | 300 |
| 铁甲 IRONCLAD | 4 点生命，每次受击后外观出现新裂纹（4 个受损阶段可见），移动最慢 | 400 |

每关 20 辆敌人从顶部 3 个生成点按固定顺序出现（同屏最多 4 辆），生成时带星光动画与保护期；出生点被占时会延迟生成。每关固定 4 辆闪烁的"道具携带者"，被玩家击毁后掉落随机道具。

### 7 类地形

| 地形 | 坦克 | 子弹 | 说明 |
| --- | --- | --- | --- |
| 空地 | 可通行 | 可通行 | — |
| 砖墙 | 阻挡 | 阻挡 | 可被子弹摧毁；每格 4 个 8×8 子块支持局部破坏 |
| 钢墙 | 阻挡 | 阻挡 | 普通子弹无法摧毁；仅 Level 3 穿甲弹可摧毁 |
| 水面 | 阻挡 | 可飞越 | 有水面动画 |
| 草丛 | 可通行 | 可通行 | 绘制在坦克上层，进入后被遮挡 |
| 冰面 | 可通行 | 可通行 | 松开/改变方向后仍会滑行，直到离开冰面或撞墙 |
| 基地 | 阻挡 | 击中即失败 | 被砖墙环包围；有正常/被摧毁两种外观与爆炸动画 |

### 6 种道具（拾取 +500 分）

| 道具 | 效果 |
| --- | --- |
| 星星 | 火力 +1（最高 Level 3） |
| 防护罩 | 约 10 秒无敌（结束前闪烁） |
| 时钟 | 敌方坦克与敌方子弹冻结约 10 秒（新生成的敌人同样被冻结；玩家、玩家子弹、道具不冻结） |
| 铲子 | 基地围墙临时变为钢墙约 18 秒（结束前闪烁；到期恢复拾取前状态；重复拾取只刷新时长） |
| 手雷 | 立即消灭场上全部活动敌人（正确计分；不伤害等待生成者/玩家/基地；不掉落道具） |
| 生命 | +1 生命 |

规则：同一时间最多 1 个道具（新道具替换旧道具）；道具带呼吸/闪烁动画，约 15 秒后自动消失；只会生成在合法、可达且无重叠的位置。

## 计分与存档

- 基础分数：侦察兵 100 / 突击兵 200 / 火力手 300 / 铁甲 400 / 道具拾取 500
- 双人模式下按击毁归属记入对应玩家；手雷击杀计入拾取者
- 每关结束显示各类型击杀统计与总分；总分跨关累积
- 存档（localStorage，键 `steel-front-save`，版本化结构 `{ v: 2, ... }`）：
  - 最高分 `highScore`、最高解锁关卡 `unlockedStage`（1–35）、音效开关 `sound`、音量 `volume`（0–1）、最后模式 `lastMode`
  - 损坏 JSON / 旧版本缺字段 / localStorage 不可用（隐私模式）均自动回落默认值，不会影响启动
  - 主菜单提供 CLEAR SAVE 入口清除存档

## 调试模式

在 URL 后加 `?debug=1` 打开页面，即可通过 `window.__TANK_BATTLE_TEST__` 使用自动化接口：

```javascript
window.__TANK_BATTLE_TEST__
// {
//   version, startGame(options), resetGame(), pauseGame(), resumeGame(),
//   stepFrames(frameCount), setPlayerInput(playerId, inputState), getSnapshot(),
//   spawnEnemy(type, position), spawnPowerUp(type, position),
//   damageTank(entityId, amount), destroyBase(), clearActiveEnemies(),
//   getInternals()  // 额外接口：直接访问 Game 实例
// }
```

`getSnapshot()` 返回可 JSON 序列化的完整状态（状态机、模式、关卡、帧号、随机种子与 RNG 状态、玩家/敌人/子弹/道具/基地、计时器、剩余敌人、分数、活动对象数量、地图与砖墙损坏数据）。正常游玩不依赖这些接口。游戏内按 F2 可叠加显示调试信息。

## 已知限制

- 不支持 Gamepad（规格中为可选项，键盘操作完整可用）
- 没有关卡选择菜单（规格未要求；主菜单显示已解锁最高关卡）
- 不设额外生命分数阈值（规格中为可选项，规则固定为"无阈值"）
- 界面文字使用系统等宽字体（规格禁止外部字体文件）
- 手雷击杀不掉落道具、铲子到期按"快照恢复"恢复墙体（均为固定规则，见上文）
